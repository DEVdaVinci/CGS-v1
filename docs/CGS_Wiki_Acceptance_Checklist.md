# CGS Wiki acceptance checklist

This checklist expands the [workspace and reference design](CGS_Wiki_Reference_Design.md) into release checks. The baseline column describes the app at `a223384`. See the [core follow-up evidence](CGS_W1_Core_Worldbuilding.md#verification-of-the-core-follow-up) and [current gap inventory](CGS_Wiki_Current_Coverage.md) for the later verified cases, remaining source and reference gaps, and their readiness.

## How to use the checklist

- **Authority.** Start with the Lucidchart exports, the owner's roadmap decisions and the [CGS field trace](CGS_Wiki_Field_Trace.md). Add compatible World Anvil workflows, then compatible Fandom workflows. If both products cover one task, record one CGS workflow and keep the distinct useful capabilities from each. Trace each entity or class, named field, connection and individual reference behavior. Record the browser control, service contract, data owner, assigned pass and proof. Update the trace and editable architecture when the underlying record or consumer changes. Justify every difference, including additions, and capture the immediate and long-term impact, or retain the source design. For deferred and temporary choices, record the target, dependency and acceptance, with migration or retirement details for temporary behavior. [Decision requirements](CGS_Wiki_Reference_Design.md#source-trace-and-design-decisions) · [Editable architecture](CGS_Codex_Local_Handoff/CGS_First_Playable_Architecture.drawio)
- **Baseline.** **Partial** means existing code or prior test evidence supports part of the outcome. **Open** means the required workflow or its proof is pending. **Later** records an explicitly scheduled dependency or owner decision. A row earns a pass when its stated browser behavior and persistence or access checks have evidence tied to the tested commit. Existing W1 test reports still apply to the behaviors they verified.
- **Reference evidence.** The cited public guides establish a documented workflow. For a reference behavior that needs a signed-in author view, record whether its exact controls and behavior were independently verified or still rely on the guide. Before closing its pass, resolve any undocumented behaviors that affect the scope or test and record the evidence. This inventory is a starting point for that review. Keep newly identified in-scope reference capabilities visible until they have a check and a disposition.
- **Completion.** Use the ordinary CGS browser with fresh and upgraded worlds. Record the data set, starting route, actions, result, and proof for each check. A shared browser run can support multiple checks when its assertions cover each one. Record invalid inputs, restricted views, and reload results where the check specifies them. W1 and W3 remain partial until all their checks pass. W5 requires the included checks below and the [milestone delivery checks](CGS_Milestones_Delivery_Plan.md#w5-phase-1-wiki-release).

### Template comparison

Translate each documented author task into a catalog type, typed variant or linked planning surface according to the CGS field trace. The public guide names Character, Condition, Document, Ethnicity, Military Unit, Item, Language, Material, Conflict, Myth or Legend, Building, Geographic Location, Settlement, Natural Law, Organization, Prose, Profession, Plot, Title, Session Report, Species, Spell, Technology, Tradition or Ritual, Vehicle, and Generic Article in its detailed list. The guide's stated total is higher than this named list. Record the actual template and functions for any additional entries during template verification.

Keep additional CGS concepts including spatial layouts, place components, authored quantities and distributions, cognition, franchise, series, scenes, shots, elements and impacts. A location template links physical space without replacing an organization that governs it. A plot or session report can reference the actual event tree and retain its own authoring order. Add a Language dictionary, family tree, organization relationship view, source document body, and plot links to their respective checks.
