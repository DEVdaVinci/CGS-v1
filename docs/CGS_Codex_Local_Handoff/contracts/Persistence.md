# CGS PostgreSQL Data Dictionary

This is the relational design for PostgreSQL 17. Use Django migrations for table and constraint creation. Use the named definitions in `domain.schema.json` for JSON payloads. Column labels and scoped keys below are normative for the first playable release. UUIDs are application-assigned. The external account table is a project-level Django account model with UUID primary key, unique username and normal Django authentication flags. Use database-generated UTC instants for created timestamps.

## Notation and data invariants

`u` is UUID, `n` is nonnegative BIGINT, `i` is nonnegative INTEGER, `t` is TIMESTAMPTZ, `b` is BOOLEAN, and `j<Name>` is JSONB validated as the named type. Text lengths are database varchar limits where specified. Each listed column is required unless followed by `?`. Text enum states get database CHECK constraints. Add a `created_at t` with a current-timestamp default to each table. Add dedicated scheduling times where listed. Default `false` or zero applies only where explicitly stated. The client sends all required fields or the wire schema's documented defaults.

Use unique target keys for composite foreign keys, including `(world_id,id)` or `(run_id,id)` where stated. All scoped references use matching source and target scopes. FK delete behavior is RESTRICT for persisted history and grant records. Keep disabled grants as rows. The first release uses append-only authored revisions, plans, publications, campaign frames, events and mutation/step receipts. Service roles have no update/delete path for immutable records. The draft, run, order and job head pointers are distinct mutable data. Use deferred foreign keys for head references populated in the same transaction as their initial immutable child. Maintain world and run clocks and counters under the world lock.

Account columns (`owner_id`, `account_id`, `author_id`, `publisher_id`, `updated_by`, `initiating_account_id`, and `principal_id`) reference the account table. Event and trigger actor IDs must match a same-world entity key and an actor in the run's pinned source. Validate rule and action-step IDs against the pinned source and plan bodies before saving their typed events.

## Authorship and sources

| Table | Columns with types | Keys and invariants |
| --- | --- | --- |
| `world` | `id u, owner_id u, title varchar(100), auth_epoch n default 0, published_seq n default 0` | PK id, owner FK to account. Owner identity controls access administration. World creation inserts an enabled owner grant. |
| `world_access` | `world_id u, account_id u, role varchar(12), capabilities j<WorldCapabilities>, enabled b` | PK world/account, FKs to world and account, lookup index account/enabled/world. Roles owner, editor, reader, player. Exactly the owner account can hold owner role. Revocation toggles enabled. |
| `world_draft` | `id u, world_id u, head_revision n default 0, active_policy_version n default 1, parent_published_id u?` | PK id, unique world_id, unique world/id, world FK. Deferred FK (id,head_revision) → draft_revision(draft_id,revision). Deferred FK (id,active_policy_version) → draft_policy(draft_id,version). Parent, when present, references same-world approved source. |
| `draft_revision` | `draft_id u, world_id u, revision n, previous_revision n?, author_id u, document j<DraftWorld>, digest char(64), provenance j<DraftProvenance>` | PK draft/revision, unique world/draft/revision. FK (world,draft) → draft. Self-FK on draft/previous_revision. At revision 0 the previous revision is null; later values equal revision minus one. Digest uses the canonical JSON encoding. |
| `entity_key` | `id u, world_id u, kind varchar(16), draft_id u, first_revision n` | PK id, unique world/id; FK (world,draft,first_revision) → draft_revision. A previously issued entity ID has one kind and world across all document versions. |
| `published_world_revision` | `id u, world_id u, number n, source_draft_id u, source_draft_revision n, parent_id u?, publisher_id u, document j<WorldSource>, digest char(64)` | PK id, unique world/id, world/number and (source_draft_id,source_draft_revision). Scoped FK to the exact draft revision; parent FK to same-world publication. number > 0. Source 1 has null parent. Advance world published_seq and update draft parent pointer in same transaction. |
| `draft_policy` | `draft_id u, world_id u, version n, policy j<DraftPolicy>, updated_by u` | PK draft/version. Scoped FK to draft. Versions start at 1. POLICY changes insert a policy row and move the active policy pointer together with the world epoch. |
| `draft_proposal` | `id u, world_id u, draft_id u, job_id u, initiating_account_id u, base_revision n, world_epoch n, guardrail_version n, group j<DraftGroup>, digest char(64)` | PK id, unique world/id, unique job_id, FK to world-scoped job and exact draft revision and guardrail version. One proposal per job. Group, digest and pins immutable. Applied status can be derived from successful edit receipt for that proposal under the draft lock. |
| `mutation_receipt` | `id u, principal_id u, operation varchar(40), scope_key varchar(128), request_key u, input_digest char(64), response_status i, result j<MutationResultRef>, world_id u?` | PK id, unique principal/operation/scope_key/request_key. Index world/created_at. The scope string is server-derived from resource IDs. Scope and references in the typed result are checked before commit and before any subsequent projection. |

For creation before a world row exists, serialize on the account row and look up the principal-scoped creation receipt. World, initial owner grant, draft, revision 0, policy version 1 and creation receipt share a transaction. Existing-world mutations lock the world row first. For a new world, start with an empty DraftWorld and a typed default policy granting no AI targets. Policy updates use expected active policy version; membership and policy writes both advance the world epoch. Historical snapshots refer to immutable policies for evidence. Current authorization uses the active policy and grants. Publish an already-sealed draft revision with the same request key to replay the original receipt. A new request against the same draft source receives `ALREADY_PUBLISHED`.

Authoring document collections use UUID-keyed maps. Source snapshots contain entity IDs and revisions, rules, links, layout, authored truths, claims and starting observation specs. Draft omissions are typed diagnostics on reads and use omitted properties in storage. Cross-reference validation checks ID ownership, role and rule kinds, validity intervals, lock/provenance scope, area bounds and reachability before publication. Check geometry and truth interval predicates in application code over one candidate document. Store an immutable group with every edit after approval and keep resolved alias-to-UUID assignments in the saved receipt.

## Campaigns and actions

| Table | Columns with types | Keys and invariants |
| --- | --- | --- |
| `campaign_run` | `id u, world_id u, source_id u, head_revision n default 0, start_tick n, title varchar(100), state varchar(12)` | PK id, unique world/id, FK world/source to same-world publication. Source immutable. Deferred heads FK (id,head_revision) → run_frame. State active or closed. Source ID is authoritative from revision 0 onward. |
| `run_access` | `world_id u, run_id u, account_id u, role varchar(12), audiences j<AudienceGrants>, actors j<IdArray>, enabled b` | PK run/account, FK world/run, FK world/account to world_access. Enabled world and run row required. Role controller or viewer. Validate actor/audience IDs against the run's source. Only a controller holds playable actor assignments. |
| `run_frame` | `run_id u, revision n, world_id u, tick n, body j<FrameBody>` | PK run/revision, unique run/tick, scoped FK world/run. Index run/tick. Start at revision 0 with the source's start tick. For this release each accepted step increments both by one. Resource state, occupancy, disclosed history and encounter flags are in body. |
| `run_order` | `id u, run_id u, world_id u, account_id u, audience varchar(44), create_key u, intent j<OrderInput>, plan_revision n?, authorized_head n, cursor i default 0, accepted_count i default 0, focus_spent i default 0, model_jobs i default 0, state varchar(24), replaced_order_id u?, planning_job_id u?, safe_issue j<SafeIssue>?` | PK id, unique run/id and world/id, unique run/account/create_key, scope FKs to run and prior order. FK (run,account) → run_access. Partial unique run_id for the four active states. Deferred FK (id,plan_revision) → order_plan. FK (run,authorized_head) → run_frame. Deferred FK (world,planning_job_id) → generation_job. Limit model_jobs to three. |
| `order_plan` | `order_id u, plan_revision n, run_id u, world_id u, base_revision n, steps j<PlanSteps>, model_job_id u?, origin varchar(24), digest char(64)` | PK order/plan_revision, unique run/order/plan_revision, FKs run/order and world/order to one order, run/base_revision to frame and world/model_job_id to generation_job. Revision starts at 1 and increments. Plan steps immutable, with unique UUIDs within the run. origin typed, verified_text, proposed_text or delegated. A candidate awaiting confirmation is not usable for advances. Record explicit acceptance transition in order state with audit actor/time in the mutation receipt. |
| `run_event` | `id u, world_id u, run_id u, before_revision n, after_revision n, rule_id u, rule_version i, actor_id u, order_id u?, plan_revision n?, step_id u?, trigger_event_id u?, detail j<EventBody>` | PK id, unique run/id and run/after_revision. FK before and after frame in same run; after = before + 1. Scoped FKs for order/plan and causative event. Exactly a player step triple (order, plan, step) or a system trigger event is present. Unique run/step_id for accepted player step; unique run/trigger_event_id/actor_id for an accepted system action. |
| `run_step_receipt` | `id u, run_id u, order_id u, principal_id u, request_key u, input_digest char(64), plan_revision n, step_id u, before_revision n, after_revision n?, event_id u?, response_status i, disposition varchar(12), reason varchar(48), projected_evidence j<ReceiptEvidence>` | PK id, unique order/principal/request_key. Scope FK run/order and run/before_revision and optional accepted-result frame and event. Disposition accepted, blocked or stale. The input plan and step record what was requested and need not reference a live plan when stale. Exactly accepted rows have event and after revision. Scope reader reprojects source refs. |
| `actor_turn` | `id u, world_id u, run_id u, trigger_event_id u, actor_id u, state varchar(12), resolved_event_id u?, diagnostic varchar(48)?` | PK id, unique run/trigger event/actor, scoped run and event FKs. state pending, accepted, held or blocked. One pending trigger per run using partial unique run_id. resolved_event_id present only for accepted. Index pending/created_at for rules loop and restore. |

Store current actor turn entitlement in the order and pending actor turn rows, along with the immutable encounter state. A pending trigger surviving restore is eligible. Clearing a hold or blocked NPC candidate changes the due row and preserves the historical frame. Replays use saved dispositions, accepted draws, scopes, and effects. Reads by event use exact pinned frames with current access. Context filters geometry, observation and actor references before returning a client DTO. Keep temporary UI request pins out of authoritative game state.

## Jobs and readouts

| Table | Columns with types | Keys and invariants |
| --- | --- | --- |
| `generation_job` | `id u, world_id u, principal_id u, kind varchar(12), state varchar(18), subject j<JobSubject>, source_pin j<JobPins>, world_epoch n, input_ref j<JobInputRef>, attempts i default 0, attempt_limit i default 2, not_before t, deadline t, lease_token u?, lease_until t?, adapter_version varchar(40), model_id varchar(100), template_version varchar(40), schema_version i, result j<JobResult>?, safe_issue j<SafeIssue>?` | PK id, unique world/id, FK to world and principal. Scope and subject keys checked by task kind. Index state/not_before and state/lease_until and state/deadline. Kind draft, plan or narration. States queued, running, succeeded, needs_input, failed, superseded or cancelled. At most two attempts. Only running jobs hold lease token and expiry. Result refers to one proposal, plan, or projected narration choice as permitted. |

Keep job input references and relevant normalized source snapshots pinned. Draft input includes the authorized author brief and structured scope. Plan input refers to the exact order submission and current planning target revision. Narration input refers to exact saved event, selected audience and permitted style. Preserve only safe model metrics and the validated output. Expose a narration result only through its job and when its scoped event is still readable. Limit stored presentation choices to the allowed finite verbal templates.

The inference claim transaction touches the job row only. Dispatch captures a currently authorized subject. The completion and reaper transactions lock world then linked draft or run/order then job. Source pins include internal history refs and current world epoch. A scope change, missing permission, expired token or terminal linked order prevents an output from attaching. When a fresh failure terminates planning, persist the job and order result together. On timeout release the order slot through the terminal-state progression. Process deterministic actor work in the separate rules loop, under the same world mutation lock. Backups retain all authority rows, source versions, frame state, receipts, pending actor turns and job lease clocks to recover these contracts.

## Index and migration checks

Create accounts and worlds first, then source/history and campaign tables, then add deferred pointer constraints and queue indexes. Seed the fixture in a separate verification database. Verify schema constraints with two PostgreSQL connections for order, access, and exact receipt races. Before a Django migration is accepted, test mismatched world IDs, a reused published revision key, inconsistent draft and run heads, and repeated steps. For reads measure access lookup by account scope, published entry lookup by world/revision, campaign frame lookup by run/revision/tick and event cursor bounds. Choose any extra indexes from measured query plans and keep first-release snapshots within the declared content caps.
