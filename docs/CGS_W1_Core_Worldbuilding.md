## Readiness and scope

W1 establishes the core authoring and reading workflows for the shared world model. The same records must support future simulation, fiction, and sourced accounts of history. An example supplies evidence about a requirement after its meaning is settled. Design requirements come from the source diagrams and the author's decisions. Check the signed-in authoring workflow, saved meaning, and historical read for each required concept.

W1 represents what may later drive decisions, including goals, knowledge, beliefs, physical state, possessions, group assignments, and navigable spatial relationships. W2 specifies and checks reusable rules, powers, and action definitions. P2 executes effects and actor decisions. W3 extends the catalog, discovery, and map presentation. W4 handles explicit import from the prototype Draft, data exchange, and model-assisted authoring. Author editing history and dated fictional history retain their separate schedules.

The [full-stack delivery table](CGS_Wiki_Reference_Design.md#delivery-order-and-proof) governs W1 through W5. The workspace pass shipped at `c092c5c`. The [historical W1 delivery plan](#remaining-w1-delivery-plan) records the sequence after `296e5ed`. The [field trace](CGS_Wiki_Field_Trace.md#additional-cgs-source-concepts) assigns the recovered physical and cognitive inputs to core authoring and schedules their runtime use separately.

### Record ownership and authoring

| Record or view | Meaning, browser workflow, and acceptance |
| --- | --- |
| **Identity and biography** | A person, organism, place, object, or group has one stable ID. Creation offers the properties and relationships appropriate to what the author is defining. A character's birth, birthplace, origin, nationality, and family belong here. The author can add related people or facts later. Verify the values and links after reload, including distinct birthplace and origin. |
| **Dated relationships and state** | A typed link names its subject, target, meaning, and effective dates. A parent link supports the inverse child view. A declared sibling and a sibling derived from a shared recorded parent carry distinguishable evidence. Physical whereabouts is an independently authored dated fact or the effect of a recorded transition. A canonical correction updates the account of an existing interval. Verify these separately from identity creation and event participation. |
| **Events and actions** | A group organizes child segments, occurrences, and actions. Participation, action performer, action target, venue, and a state effect each express distinct information. An entity article shows its linked events in the shared outline, with enclosing groups for context. Verify that a group has the same date range on its article and on the world timeline. Establish whereabouts between events only when a dated fact or effect supports it. |
| **Sources and uncertainty** | A source can be a document, artifact, recording, or person. A claim can point to it independently of who stated or learned it. The contract distinguishes exact time, uncertain placement within a range, duration, and an unknown date. Only exact effective boundaries apply automatic canonical transitions. Verify two conflicting sourced accounts can coexist and that an uncertain event date cannot silently supply an exact effect time. |
| **Downstream readers** | A consumer requests an authorized world and time or period, with the applicable viewpoint. Return stable references and visible evidence. A run owns its live state and a work owns its selection and reveal order. Verify an editorial read from authored history and a simulation starting read through the same world interface. Simulated actions and work-specific discoveries retain their own context. |

### Core design and compatibility

- **Identity, family, and linked history.** Keep existing IDs and facts. Separate character definition from temporary position, give family relations recognizable controls, and present the same nested event records from articles and the world timeline. Make performer links useful for people, organizations, and authored devices. Existing API payloads and prior location facts retain their meaning. Verify biography, inverse and derived family links, non-acting participants, related actions, and context groups through the ordinary browser.
- **Time, spatial state, and evidence.** Keep the exact clock for existing intervals. Distinguish containment, physical whereabouts, residence, and event venue at the read and write boundaries. Preserve legacy records and mark genuinely ambiguous ones for author review. Check competing transitions, measurement units, historical waypoints, and fictional-viewpoint selection separately.
- **W1 acceptance and upgrade.** Trace each required type, field and connection to its browser workflow, API validation, data owner, consumer, and passing evidence. Reopen an existing world as well as a fresh world. Keep findings, missing workflows, design decisions and deferred features visible by check ID. W1 acceptance also includes the workspace and image map workflows.

### Nested timeline contract

| Decision | Meaning in W1 |
| --- | --- |
| Records and depth | Use a single world-scoped identity and an optional parent link for each timeline node. An **event group** is a container and can have child groups, recorded actions, or other occurrences. A recorded action or occurrence is a leaf and can also stand alone at the top level. Groups have names, sources, notes, and optional links to people, places or items. A group can be empty while the author outlines it. Depth follows the content. The browser renders branches as they are expanded from one scoped timeline response. |
| Organization and references | Each node has at most one structural parent. A leaf can link to several people or places, and another group can cross-reference the same leaf by ID. A cross-reference opens the original record and does not copy it or its effects. The outline can express stages of an errand or parallel theaters of a larger event. Sibling order is author-controlled for reading. |
| Chronology | A dated leaf has a start and an optional end. Its effective tick controls any state changes, defaults to the start, and must fall within the recorded span. An author can give a group an enclosing start and end, or let it show the span of its dated descendants. Undated groups without dated descendants show as unscheduled. An explicitly dated group accepts children within its bounds, and parallel branches can overlap. The chronology view sorts dated leaves by world time independently of outline order. A simultaneous tick has no implied causal order. |
| State and correction | Groups organize and summarize. A dated leaf owns any explicitly saved effects, including multiple changes at one tick. A leaf can also record participation without changing state. Grouping, reordering and reparenting preserve leaf IDs, dates and effects. Child dates change only through explicit corrections. To decompose a legacy occurrence with effects, make a group around the original leaf so existing links still land on the same record. W2 defines reusable actions and rule checks, and P2 interprets them in play. |
| Writing and validation | Index parent and sibling lookups within the world. Create, move or reorder under the existing authorized change transaction and receipt. Reject invalid parents, self-links, ancestor cycles, and a move outside explicit enclosing dates. Show the affected nodes and dates for repair. Bounds derived from children update through the read projection. Author edits to a group’s date do not retime its children. Keep the original B0 records as standalone leaves, preserving their time, ID, receipts and linked effects. |
| Browser and viewpoints | Offer **Outline** and **Chronology** from both the world timeline and an entity's **Dated events**. The article lists directly linked leaves and marks additional ancestor groups as enclosing context. All views use the same group dates. In the world outline add, move, and reorder groups and actions. Filter by involvement, place or date, preserving the path for matches. The scoped projection determines which groups, links, and counts can be shown. |

World Anvil's timeline and era navigation is a reference for browsing by date. Fandom's grouped navigation and links to sections are a reference for keeping related material findable. CGS uses its own event hierarchy and state model so both kinds of browsing resolve the same underlying records. [World Anvil timeline tutorial](https://www.worldanvil.com/learn/beginner-tutorials/get-started-timelines) · [Fandom navigation help](https://community.fandom.com/wiki/Help%3ANavigation)

### Defaults for implementation

- Keep the current ordered world positions and half-open intervals. The start is inclusive and the end is exclusive. A world can declare a simple calendar with a day tick and an authored fixed year length for the initial age calculation. An unconfigured world keeps its original tick labels and shows age as unknown. More elaborate calendars can use the same ordered clock when requirements call for them. A blank death date describes missing information.
- Use exact integer units for dimensions such as existing height and new coordinates. Carry fractional author-defined quantities as a decimal value and unit with exact comparison. Use scoped definitions or controlled choices for repeated values that matter to a consumer. Values such as currency and energy can be defined by the author without hard-coding one franchise's terminology.
- Use a declarative catalog for supported property and relationship meaning, target kinds, cardinality, units, labels, and forms. New definitions can reuse it. Keep arbitrary expression and effect authoring in W2.
- A missing or restricted fact, an inconsistent canon slot, and a value supplied by a default have distinguishable read states. An explicit personal value overrides an eligible default. The character preview receives the character's recorded evidence and beliefs. Authoring scope gates access to the underlying world separately. Design the projection before exposing backlinks, inferred defaults, or layout data.

### Effective slots and transitions

| Kind of data | What counts as one change or conflict |
| --- | --- |
| Exclusive property or relationship | Unqualified properties such as height, and exclusive relations such as direct physical location, have one effective slot per subject. Two incompatible canon records for that slot produce a finding. A grouped transition with incompatible writes to the same slot fails as a unit. |
| Qualified state | A resource amount is scoped to the subject and the resource definition. A body-part condition is scoped to the part and condition. An event can change two different resources or two different parts at the same time. Changes to one resource have no effect on the others. |
| Repeatable fact or relationship | Aliases, family members, group memberships, and goal links allow multiple distinct values or edges. Their identity includes the endpoint or value and applicable context. Duplicate writes are checked within that identity. Closing one dated link leaves its neighbors intact. Inverse views read the same link. |
| Evidence and derived state | Author corrections to canon can trigger a source-changed finding. Captured observations retain their received value. The scoped response applies visibility before deriving contents or exposing default sources, then withholds any unavailable detail. |

## Character and spatial implementation details

### Pass A — Character records and viewpoints

1. **Baseline and schema.** Use the existing Wiki entry, author access, change receipt, and time query boundaries. Extend stable kinds for the minimum reusable reference library. Keep scalar assertions and their IDs. Add a common dated relationship representation for new links, with explicit source, target, optional context, effective interval, provenance and visibility. Use stable definitions for supported typed properties. Fit resources, traits, and assignments into those primitives before adding narrower storage.
2. **Effective values and evidence.** Add inheritance and scoped read logic, then record and resolve claims, observations, and beliefs using typed references and captured inputs. Run direct PostgreSQL checks for matching defaults, overrides, conflicting defaults, false reports, past knowledge and permissions before exposing the new projection broadly.
3. **Browser character workflow.** Expand the existing Wiki create form and article sections. Reuse the type-aware entry picker and preview controls. Offer inline links to the minimal definitions and keep the normal article navigation. Exercise W1-02 and the character-side W1-05 cases through reload on a clean database. At this midpoint report W1 as partial.

### Pass B — Spatial and temporal integration

1. **Normalize legacy links.** Expose old character and item `located_in` values as physical whereabouts and old place `located_in` values as parent relationships. Preserve the original assertion IDs, payload compatibility, dates, source links, and event references. Keep one canonical storage path for each mapped link. A legacy case with ambiguous meaning, such as an old group location with no indication whether it was headquarters or an actual position, retains its original value and gets an author review state. Apply new structural rules to new changes and report pre-existing invalid structures for review.
2. **Add layout and relationship editing.** Author origins, containment, residences, destination, measured floor plans, and route endpoints from the ordinary **Places** and character article routes. Validate the final candidate graph over affected intervals. Validate child and parent scope, positive layout dimensions, endpoint bounds, and route references. A co-effective containment cycle fails the grouped change. Historical links that never overlap in time can coexist.
3. **Generalize grouped transitions.** Keep the existing save transaction, edit counter and request receipts. Extend the event command with explicit operations for typed facts and dated links. Read before and after from linked prior and resulting records, including time zero and corrected dates. Validate a complete candidate before commit so the order in which form fields arrived cannot create a partial move, injury, or possession transfer. Retiming updates every boundary the event owns. Preserve earlier request normalization and repeat the original B0 event receipt case.
4. **Build the event outline and chronology.** Add group and leaf authoring, validated hierarchy edits, time and relationship filters, and stable links from either view. Exercise a deeply nested errand, overlapping branches and changes to outline order. Verify the same dated actions and effects in chronology and on the related articles.
5. **Complete W1 acceptance.** Run both normal browser workflows, PostgreSQL correctness and compatibility checks, and a saved-data upgrade rehearsal against an isolated copy. Verify that the Draft route still opens, the existing Wiki links resolve and persisted values retain their meaning, and the new workflow succeeds after migration and on a fresh database. Use a local Compose rollout only after the tested migration is ready for the working app.
