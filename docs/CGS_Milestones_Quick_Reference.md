# CGS milestones at a glance

**Current position** — B0 is verified and W1 remains open. W1 has the Worlds dashboard, world homes, article and map navigation, linked character variants, scoped causal accounts, dated anatomy and resource records, and shared subgoals. Articles can store uncertain lifecycle dates and link a past sighting while keeping canonical location separate. W2 follows W1 acceptance. W5 is the complete Phase 1 Wiki. P3 is the first complete tabletop release. [Evidence and open checks](CGS_Wiki_Current_Coverage.md#current-assessment) · [Detailed milestone plan](CGS_Milestones_Delivery_Plan.md) · [Wiki acceptance checklist](CGS_Wiki_Acceptance_Checklist.md)

**Remaining Wiki work** — The [implementation checklist](CGS_Wiki_Current_Coverage.md#remaining-work-through-the-complete-wiki) orders the open work by milestone and links it to the detailed inventory. The [direct-access pass](CGS_W1_Core_Worldbuilding.md#direct-access-from-home-catalogs-and-articles) gives the current tools and historical views clear browser entry points. Follow the [sprint rules](../AGENTS.md#user-instructions-and-approval) for any change to the requested sequence or deliverable.

- **[B0 · Working foundation](CGS_Milestones_Delivery_Plan.md#b0-working-foundation)** — Already in the browser. Create basic character and place articles, link events, and inspect dated changes on the same character. This verifies the workflow. The source-designed character and place coverage is W1.
- **[W1 · Redesign the workspace and finish core worldbuilding](CGS_Milestones_Delivery_Plan.md#w1-core-worldbuilding)** — Redesign the browser home, navigation and articles with working Items, Vehicles, Maps and contextual history. Ship an image map and saved pins. Complete source-backed character, place, timeline and knowledge fields with their forms, validation and storage. Each pass has its own proof.
- **[W2 · Author actions, powers, and rules](CGS_Milestones_Delivery_Plan.md#w2-actions-powers-and-rule-checking)** — First define the general-purpose toolbox and what it can express. Then ship browser authoring and explainable validation for prerequisites, costs, effects, progression and exceptions. The same checker must handle a power, an institutional rule and a physical limit. This finishes the Phase 1 rule authoring layer. Live execution belongs to P2.
- **[W3 · Finish manual Wiki authoring](CGS_Milestones_Delivery_Plan.md#w3-full-catalog-and-discovery)** — Build the remaining named entities and fields, typed relationships, articles and discovery, map and timeline tools, and media and project planning. Add the relevant World Anvil and Fandom workflows across the browser, services, and storage. At this point manual Wiki authoring is complete. Assisted authoring and release checks follow.
- **[W4 · Add assisted authoring and data exchange](CGS_Milestones_Delivery_Plan.md#w4-assisted-authoring-and-data-exchange)** — Approve scoped AI proposals into a draft and publish to canon separately. Preview imports and export and restore a world with its dates and links intact. Use the ordinary browser forms when the model is unavailable. At this point the Wiki features are in place. W5 verifies the assembled release.
- **[W5 · Release the complete Phase 1 Wiki](CGS_Milestones_Delivery_Plan.md#w5-phase-1-wiki-release)** — Verify all agreed browser capabilities across distinct domains, including a non-adventure setting. Verify fresh install, upgrade, recovery, access controls, and downstream reads. This is the milestone where the Wiki is expected to meet the agreed design and authoring standard.
- **[P2 · Execute events and bounded decisions](CGS_Milestones_Delivery_Plan.md#p2-shared-event-and-decision-engine)** — Turn supported actions into rule-checked events. Verify that the same inputs produce the same effects and that an actor chooses from the information they have. Authors can try the engine in a browser test run. This is the engine finish line for the first tabletop release.
- **[P3 · Play a complete tabletop dungeon](CGS_Milestones_Delivery_Plan.md#p3-first-playable-tabletop)** — Prepare a dungeon through the Wiki, including a scoped assisted draft that an author reviews and publishes. Start from that approved source. Explore, resolve an encounter, advance a character, and save and resume. Change a Wiki rule or layout and show how it changes a new run. This is the first complete playable release.
- **[S1 · Try the first story workflow](CGS_Milestones_Delivery_Plan.md#s1-first-story-workflow)** — Generate a short, sourced outline and scene from authorized Wiki history. Add accepted play events when available. Review what each character and the audience can know.

For each milestone, the detailed plan shows what you can try in the browser and what evidence counts as a pass. The field trace records what each pass covers. Design changes have a written reason and trade-off, and a deferred item has a named prerequisite and completion check. A build with unfinished milestone checks remains partial.
