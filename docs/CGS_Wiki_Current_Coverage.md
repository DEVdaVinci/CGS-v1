### Implementation strategy

Work in browser-sized increments that include their supporting data and validation. Close visible W1 access, health correctness and integrated W1 proof before W2. For each pass, take the source rows from the inventory, design the page and its expected fields, use or extend the shared Django writer and PostgreSQL references, and run a normal browser save, reopen and invalid case. Test the same feature via any alternate creation path it shares. When a record changes over time, verify the earlier and later read on the same identity.

Build W2's rule contract before evaluator-dependent tools. Start W3 with the shared types and permissions, then deliver the editor and discovery, maps and chronology, and author planning as independently usable passes. W4 reuses the checked writer and scoped views. W5 checks the assembled product against each source and both reference workflows. Report what was verified in disposable Compose, what is serving locally, and what is still open. After each verified coding pass, commit with the design and evidence, push the feature branch, and verify the remote head.

### Design differences that need individual dispositions

The [field trace](CGS_Wiki_Field_Trace.md) explains the existing representations. The following differences already affect the work plan. Each still needs a field-level result and any material change needs the owner's approval.

| Current representation | Benefit and follow-up |
| --- | --- |
| Physical whereabouts is dated separately from Character creation. | A character keeps one identity while moving. Browser proof must show higher-level affiliations, event participation, residence and actual whereabouts independently. |
| Dates use an integer world clock. | Stable raw ticks support existing history, while DateTime precision and richer calendar semantics still need a contract. Decide how changing a calendar affects previously presented dates and age before a migration. |
| Named dimensions use centimeters and mass uses kilograms. | Typed numbers make existing records comparable. Review whether the source's weight needs a separately authored force measurement. Computation requires a unit-aware expression contract. |
| Vehicle uses the Item identity and a dedicated catalog. | The same vehicle can be found in both catalogs and preserve old IDs. A catalog label leaves vehicle-specific fields and linked parts open. |
| Role, Job and Title are separate dated links with a shared definition kind. | Existing assignments can change independently while reusing definitions. Confirm the necessary distinct profession/authority fields and where relationships themselves own criteria, costs and benefits. |
| Source statements, observations and canon have separate records. | A correction can preserve what an actor learned. Verify provenance separately across corrections, date changes and audience disclosure. |
